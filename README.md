# MetroHackaton

Хакатон «Сириус» × Метрополитен. Вектор 2: управление насыщенностью линии подвижным составом в зависимости от пассажиропотока (Линия 1, Санкт-Петербург).

## Задача
Сравнивать фактический пассажиропоток с расчётным для планового графика и при отклонении выдавать диспетчеру рекомендацию: сколько составов выпустить или придержать, на каком направлении и по какой причине.

## Идея решения
1. **База (медиана):** типичный вход по ключу станция × тип дня × 15-минутный слот.
2. **Прогноз:** бустинг (LightGBM/CatBoost) на остаток от медианы, горизонты 15/30/60/120 мин. Признаки: календарь, погода (Open-Meteo), события, лаги соседних станций.
3. **Нагрузка на перегонах:** вход прогноза + доля вышедших по станциям (оценка по массе вагона из РПДП) и вместимость состава 1458 пасс.
4. **Решающие правила:** добавить состав (горячий резерв ~7 мин, холодный ~30 мин), зонный оборот (Пл. Восстания, Пл. Ленина), изменить интервал или придержать состав. Учитываются ограничения линии.
5. **Объяснение:** вклад факторов (SHAP) в текстовом виде для диспетчера.
6. **UI:** мнемосхема линии, рекомендация с дедлайном и причинами, what-if сценарии.

## Данные (в репозиторий не входят)
- Входы на станции по 15 минут: февраль, май, июль, сентябрь 2026, 24 станции (вестибюли).
- Входы по часам: январь – сентябрь 2026.
- График движения, вместимость составов, парность, пример нештатной ситуации, выгрузка РПДП (скриншоты).
- Погода: Open-Meteo, архив по часам.

## Первые наблюдения
- Сутки метро считаем с 03:00.
- Медиана по станции × типу дня × слоту даёт WAPE около 12% на сентябре. По схеме «месяц в проверку»: февраль 14%, май 12%, июль 20%, сентябрь 12%. Июль сложнее остальных, так как в обучении нет лета.
- Пятница отличается от пн–чт: поток днём (15–17 ч) выше на 13–20%, в 18:00 ниже на 24%. Тип дня «будни» нужно делить.
- Выбросы сосредоточены вокруг праздничных и предпраздничных дат (например, 8–11 мая), 1 сентября и отдельных дней.

## Ограничения и допущения
- Данных по отдельным поездам нет, движение для демо строится по графику.
- Время хода между станциями принято 2,6 мин (оценка по обороту 99 мин), требует уточнения.
- Доля вышедших пассажиров пока оценивается приближённо, нужна выгрузка РПДП.
